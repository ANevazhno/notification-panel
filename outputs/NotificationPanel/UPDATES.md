# Обновления панели

Версия 0.3.0 добавляет экран «Настройки → Обновления приложения». Первый APK с этой функцией нужно установить вручную поверх 0.2.0, не удаляя приложение. Ключ подписи и package name сохранены.

## Что готово

Проверка по кнопке, описание изменений, HTTPS-загрузка APK, ограничение размера (64 МиБ), SHA-256, проверка package name, номера версии и совпадения текущих сертификатов. Android дополнительно проверяет APK при установке. Ротация ключа в этом прототипе не поддерживается. Переходы HTTPS → HTTP запрещены. APK загружается во внутренний cache; установщик получает временный доступ только к одному APK, только на чтение. Доступ к общим файлам телефона не требуется.

Установка происходит через Android с подтверждением пользователя. При необходимости панель открывает настройку «Установка неизвестных приложений». После возврата с выданным разрешением запускается установщик. Отказ не удаляет текущую версию. Уже загруженный APK доступен после перезапуска панели, пока Android не очистил cache.

Запросы выполняются только по кнопке, автоматических фоновых проверок нет. Загрузка продолжается при обычном уходе с экрана, пока жив процесс; при его завершении нужно повторить загрузку. Докачки нет. Повторное открытие экрана во время загрузки может потребовать ещё одного открытия после завершения для обновления статуса. Тексты уведомлений не отправляются. Сервер видит обычный HTTPS-запрос, включая IP-адрес клиента.

## Что ещё требуется

GitHub Releases подключён в версии 0.3.1. Репозиторий: https://github.com/ANevazhno/notification-panel. Адрес по умолчанию встроен в APK. Опубликованы подписанный APK и latest.json; ключ подписи и исходники не опубликованы.

Бесплатный вариант — отдельный публичный GitHub-репозиторий для релизов. Исходники и ключ подписи публиковать не требуется. На каждый релиз загрузить два файла: подписанный APK и latest.json. Постоянный адрес в панели:

`https://github.com/ANevazhno/notification-panel/releases/latest/download/latest.json`

В latest.json должен быть адрес APK конкретного релиза, например:

`https://github.com/ANevazhno/notification-panel/releases/download/v0.3.0/NotificationPanel-0.3.0.apk`

Не включать токены в адрес. Этот прототип рассчитан на общедоступные HTTPS-файлы, не на приватный GitHub API с авторизацией. Альтернатива — собственный HTTPS-сервер со статическими файлами.

## Подготовка релиза

1. Увеличить versionCode и versionName в AndroidManifest.xml.
2. Собрать тем же ключом. Хранить его резервную копию приватно; не загружать в репозиторий. Без него обновление поверх установленной версии невозможно.
3. Создать latest.json скриптом New-UpdateManifest.ps1:

```powershell
.\New-UpdateManifest.ps1 -Apk ..\NotificationPanel-0.3.0.apk -ApkUrl 'https://github.com/ANevazhno/notification-panel/releases/download/v0.3.0/NotificationPanel-0.3.0.apk' -VersionCode 3 -VersionName '0.3.0' -Notes 'Обновления по воздуху и доступ к названиям приложений.' -Output ..\latest.json
```

4. Опубликовать APK и JSON вместе в новом релизе. Не заменять APK другим содержимым после публикации.
5. Ввести постоянный адрес JSON в настройках панели и проверить. При одинаковой версии должно появиться «Установлена актуальная версия». Для полного теста установки нужен следующий релиз с большим versionCode.

## Проверено

JVM: политика HTTPS, запрет адресов с паролем/фрагментом, лимит размера, SHA-256 и повреждённая сумма.

Android 16 AOSP: экран обновлений, принятие новой версии с тем же ключом, отклонение чужого пакета, старой версии, другого ключа и несовпадения версии JSON/APK; чтение APK через provider, запрет записи и иных путей. См. ../PanelTestStand/update-test-results.txt.

Публичная загрузка latest.json и APK 0.3.1 проверена без авторизации, SHA-256 совпадает. Установка поверх 0.3.0 проверена через ADB на эмуляторе. Полный цикл установки через экран обновлений на OxygenOS ещё не проверен. Реальный телефон подтвердил отображение панели 0.2.0; действия исходных приложений требуют отдельных проверок.
