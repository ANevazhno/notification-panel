# Продолжение разработки на другом ПК

Снимок: 18 ноября 2026. Выпуск 0.11.15 проверен публичной загрузкой.

## Состояние

- Native Android Java / Android Views, без Gradle. Package `local.notificationpanel`.
- Исходники и последний опубликованный релиз: 0.11.15 (41), minSdk 28, targetSdk 36.
- Группировка уведомлений, действия источника, виджет, погода, боковая кнопка,
  SMS с дедупликацией, интеграция Spleta, опциональный перенос обычных текстовых
  уведомлений из системной шторки, карточка музыки через MediaSession.
- Музыка: предыдущий/следующий, pause/play, сохранение карточки на паузе,
  скрытие после stop; в 0.11.15 — ручное закрытие карточки. Пользователь
  сообщил об установке 0.11.14, но установка 0.11.15 и поведение новой кнопки на OnePlus ещё не проверены.
- Основное устройство: OnePlus 13s / CPH2723, OxygenOS 16. Проверки также проводились
  на эмуляторе Android 16. Подробности и границы проверок — DESIGN.md и TESTING.md.
- Пользователь сообщил об установке OTA 0.11.14 и о том, что Яндекс Музыка остаётся видимой. По его поручению опубликована 0.11.15 с ручным скрытием карточки; установка новой версии на телефоне ещё не подтверждена.

## Быстрый старт (Windows)

1. Установить Git, JDK 17 и Android SDK: platform android-36, build-tools с aapt2,
   d8, zipalign и apksigner, platform-tools (adb). Ранее применялся JDK 17.0.20.1+1.
2. Клонировать:

```powershell
git clone https://github.com/ANevazhno/notification-panel.git C:\Dev\notification-panel
cd C:\Dev\notification-panel
```

3. Перенести **исходный panel-dev.jks приватно**, отдельно от Git.
   На старом ПК исходник находился в
   `C:\Users\Rabot\Documents\Codex\2026-11-03\lfd\work\panel\panel-dev.jks`.
   При подготовке переноса сделана копия в `E:\Codex\Шторка\private-transfer\panel-dev.jks`.
   Копию хранить на защищённом носителе. Без исходного ключа обновление поверх
   установленной версии невозможно. Скрипт создаёт новый ключ при отсутствии файла:
   перед сборкой обновления обязательно проверить существование исходного ключа.
4. Пример сборки (подставить реальные пути; WorkDir должен быть новым/пустым):

```powershell
$key = 'C:\Private\panel-dev.jks'
if (!(Test-Path -LiteralPath $key)) { throw 'Перенесите исходный ключ подписи' }
.\outputs\NotificationPanel\build.ps1 `
  -JdkHome 'C:\Tools\jdk-17' `
  -AndroidJar 'C:\Android\Sdk\platforms\android-36\android.jar' `
  -BuildTools 'C:\Android\Sdk\build-tools\36.0.0' `
  -WorkDir 'C:\Temp\panel-build-new' `
  -KeyStore $key
```

Скрипт запускает GroupingTest и UpdateCoreTest, собирает и проверяет подпись APK.
При текущем манифесте результат: `outputs/NotificationPanel-0.11.15.apk`.
Не заменять уже опубликованный APK пересборкой той же версии.
Для проверки сначала использовать эмулятор. На реальном устройстве установка
обновления сохраняет данные только при совпадающей подписи; не удалять приложение.

## Контекст решений

DESIGN.md — основная история интерфейса и поведения. Сохранять тёмные компактные
стопки, часы/погоду, существующие жесты и размеры. Последующие записи уточняют
ранние; заголовок старого README 0.6.1 не отражает актуальную версию.

Режим «Только в нашей Шторке» включается явно. Сначала надёжно сохраняется локальная
копия, затем отменяется исходное уведомление. Звонки, музыка, будильники, навигация,
служебные/неудаляемые карточки и другие профили защищены. Не сериализовать PendingIntent.
Копии ограничены 200 карточками и 7 днями. Действие «Открыть» не означает «Прочитать».

## Spleta — отдельный проект

Портал: https://github.com/ANevazhno/sk-energioresurs-portal,
локальная копия переноса имела commit `9789bd10dadd92847c434794ffe03fd68bbced6e`
(2.57). Она не содержит незакоммиченных изменений. Не включена повторно сюда.
Android использует личный API уведомлений и SSE `/api/notifications/stream`,
вход в WebView, без Firebase/Google. Серверный код и его AGENTS.md читать в отдельном
репозитории. Рабочие credentials, БД и серверные операции не требуются для сборки
Android. Документация предыдущего этапа сообщает о выпуске портала 2.57; это
исторический факт, не повторная проверка сервера 16 ноября.

## Выпуск 0.11.14 после переноса

Музыкальная карточка теперь показывается только при наличии живого системного
медиа-уведомления с тем же пакетом и токеном MediaSession. Пауза с оставшимся
уведомлением сохраняет карточку, удаление уведомления скрывает её, повторная
публикация восстанавливает. Изменены MusicCard, NotificationBridge и сохранённый
music instrumentation fixture (его уведомление синтетическое: доставка через ОС
проверяется только на устройстве). На этой машине скачаны и сверены JDK 17,
Android SDK 36 и Build Tools 36.0.0; Linux-сборка кандидата 0.11.14,
GroupingTest, UpdateCoreTest и проверка подписи v3 прошли. Исходный ключ в
/home/jarvis/private-transfer/panel-dev.jks вне Git имеет режим 600 и тот же
сертификат, что у опубликованного APK 0.11.13. Android instrumentation и проверка
Яндекс Музыки на OnePlus не проводились; установка пользователем не подтверждена.
Релиз v0.11.14 опубликован 17 ноября 2026. Публичные latest.json и APK скачаны
без авторизации и побайтно совпали с локальными артефактами; SHA-256 APK:
5d1efc76f46510750d5490135102321f8921bb657fc7204881b2f158d8574735.
Системные карточки истории воспроизведения без живого уведомления этим правилом
не воспроизводятся.

## Релиз 0.11.15 — ручное скрытие музыки, исключения и Spleta

По запросу пользователя после установки 0.11.14 добавлена кнопка закрытия
музыкальной карточки в Шторке без отправки команд плееру и без отмены системного
уведомления. Восстановление — при наблюдаемом переходе пауза→играет либо новом
медиасеансе; переход, пока панель закрыта, может быть не замечен. Скрытие
держится в памяти процесса; после перезапуска приложения может сброситься.
В настройках «Исключённые приложения» направление переключателя изменено:
выключено означает исключено, включено — показывать в Шторке. Данные не мигрируют.
Для Spleta добавлены ранняя JobScheduler-синхронизация после OTA/boot
(параллельные задания 731/732 завершаются независимо),
синхронизация при открытии приложения/первом SSE, повтор при временно
недоступной cookie/401 и объединение SSE-сигналов во время занятого sync.
Отвергнутая cookie не отправляется на сервер повторно до нового входа; при
отсутствии cookie локальные приватные карточки инвалидируются синхронизацией.
В настройках отдельно виден статус API и фонового соединения. Истёкшая сессия
портала всё равно требует входа через WebView. Сервер и cookies не изменялись;
реальный OTA/OnePlus сценарий для этих исправлений ещё не проверен.
Linux-сборка SDK 36/JDK 17 и JVM-тесты GroupingTest, MediaDismissalTest,
UpdateCoreTest прошли, APK с исходной подписью v3 версии 0.11.15 (41) собран.
Instrumentation fixture компилируется, но Android-устройство и эмулятор здесь
недоступны; тест с Яндекс Музыкой не проводился. См. DESIGN.md.
Релиз опубликован по просьбе пользователя 18 ноября 2026:
https://github.com/ANevazhno/notification-panel/releases/tag/v0.11.15.
Публичные latest.json и APK скачаны без авторизации и побайтно совпали с
локальными артефактами; SHA-256 APK:
21abc52fe7ac4e7a676a0bf2e2e729372c58db2f4a0708d6f13c96c9942e2c89.
Сертификат подписи совпадает с опубликованным APK 0.11.14.
OAuth-токен GitHub CLI после выпуска удалён из локальных файлов; ключ подписи
остался вне репозитория. Установка на телефоне ещё не подтверждена.
